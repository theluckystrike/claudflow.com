How the comparison works

Both models face the same transcript. On turn i the model re-reads the system prompt plus every tool record from earlier turns, then reads and writes the new records for this turn. The formula per turn is

turn_cost(i) = ( sys + (i-1) * T * tok ) * pin / 1e6 + T * tok * (1 - outFrac) * pin / 1e6 + T * tok * outFrac * pout / 1e6

The run total sums this over the turn count you give each model. Prices are editable so you can check batch rates or future list changes; the defaults are the published Opus 5.5 and Sonnet 5 list rates.

Reading the break-even turn ratio

The verdict line reports the turn ratio at which Sonnet's total catches up to Opus. If Opus reliably finishes in fewer turns than that ratio, Opus is cheaper for the whole run. If not, Sonnet wins on cost and the difference goes to quality judgement, not arithmetic.

  • Same turn count on both models: Opus costs about 1.67x Sonnet at default rates (5/3 on input and on output), so Sonnet wins on cost alone.
  • Opus at half the turns usually still costs less than Sonnet at default rates. It approaches parity as the system prompt grows, because the big first-turn re-read lands on whichever model runs the first turn. Run your own numbers above.
  • Per-turn cost grows linearly for both models because the transcript re-read grows every turn. The last turn is always the most expensive one.

Frequently asked

Why does the last turn cost more than the first?

The transcript is longer. Every earlier tool record is re-read as input on each later turn, so per-turn cost rises linearly with turn number.

Does this include caching?

No. This page compares raw list-rate costs with the full transcript re-read priced at the input rate. Caching discounts the re-read portion and is modeled separately in the agent loop cost calculator.

Are the prices in the list exact?

They are the Anthropic published list rates as of 2026-09-28, and every field is editable, so you can substitute negotiated or batch rates.
